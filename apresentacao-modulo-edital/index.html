1.10 Snapshot RN08 — auditabilidade do edital

Como funciona

  • No momento da publicação do edital, o sistema congela uma cópia completa de todas as configurações referenciadas (modalidades, etapas, cidades, vagas...)
  • Cada snapshot recebe um hash SHA-256 único, calculado de forma determinística
  • Alterações posteriores em configurações não retroagem para editais já publicados
  • Auditor pode exportar o snapshot completo como JSON e validar o hash a qualquer momento

Por que importa

  • Conformidade com Lei 14.129/2021 (Governo Digital) — transparência ativa
  • Defesa jurídica contra alegações de "as regras mudaram durante o processo"
  • Reprodutibilidade — qualquer auditor pode re-classificar candidatos com o snapshot exato do dia da publicação
  • LGPD — trilha de auditoria do que era visível no momento

RN08 (regra de negócio): "Todos os parâmetros configuráveis ficam congelados ao serem vinculados a um edital. Alterações retroativas são proibidas para preservar integridade dos resultados e auditabilidade."

2.7 Snapshot RN08 — canonicalização determinística

// 1. Denormaliza configurações referenciadas
function buildSnapshot(state) {
  return {
    versao_snapshot: 1,
    edital_uuid: state.id,
    tipo: denormSingle(Keys.TIPOS_EDITAL, ...),
    modalidades: denormMany(Keys.MODALIDADES, ...),
    etapas: ...,
    vagas: ...,
    obrigatoriedades_avaliadas: validate(state).aplicaveis
  };
}

// 2. Ordenação determinística por código
function denormMany(key, predicate) {
  return items.filter(predicate)
    .map(omitMeta)
    .sort((a, b) => {            // byte-sort puro
      if (a.codigo < b.codigo) return -1;
      if (a.codigo > b.codigo) return 1;
      return 0;
    });
}

// 3. Hash SHA-256 sobre serialização canônica
async function computeHash(snapshot) {
  const canonical = canonicalStringify(snapshot);
  const buffer = new TextEncoder().encode(canonical);
  const hashBuf = await crypto.subtle
                    .digest('SHA-256', buffer);
  return hex(hashBuf);
}

Propriedades garantidas

  • Determinismo cross-engine: byte-sort (não localeCompare) — mesmo resultado em Node, Chrome, Firefox
  • Ordem de chaves determinística: canonicalStringify ordena recursivamente
  • Metadados voláteis omitidos: omitMeta remove id, criadoEm, atualizadoEm, ativo
  • Fallback literal para FKs: ex. unidade_ofertante_sigla congelada — se Unidade for deletada depois, snapshot preserva
  • Mesmo edital → sempre mesmo hash: dois admins editando configuração sem mudar conteúdo do edital não alteram hash

2.9 Permissionamento OIDC (v3.3.2)

Arquitetura PBAC + ABAC contextual

  • PBAC (Policy-Based): permissões granulares por recurso × ação (ex.: selecao:edital:publicar, configuracoes:modalidade:editar)
  • ABAC contextual: contexto de Unidade (UnidadeDona, UnidadesAdministradas) limita escopo
  • Sem herança automática (R8): PROEG (pai) não vê CEPS (filha) por default — auditoria sempre explícita
  • IAuthorizationDecisionService: contrato formal; todo command/query sensível passa por aqui
  • EscopoAuditoria: concessão temporária com vigência + justificativa + base legal LGPD

2.11 Regras de autorização — invariantes binding

R8 — Sem herança automática

PROEG (pai de CEPS no organograma) não tem acesso a editais CEPS por default. Hierarquia institucional é para organograma e cadastro, não para autorização.

Auditoria sempre explícita

Acesso de auditor a dado sensível exige EscopoAuditoria com: (usuario, modulo, unidadeCodigo?, processoId?, validoDe, validoAte, concedidoPor, justificativa, baseLegal).

Expiração obrigatória

Toda concessão de exceção/escopo de auditoria tem validoAte obrigatório. "Indefinido" só para grupos base com recertificação semestral.

Dupla aprovação para concessões poderosas

Conceder IsPlataformaAdmin, criar EscopoAuditoria global ou exportar dados sensíveis exige aprovação de 2 admins distintos.

X-On-Behalf-Of-Unidade não é confiável

Atuação em nome de outra unidade exige AtuacaoInstitucional + EscopoDelegacao em banco — header HTTP é falsificável.

Auditoria no limite do caso de uso

Não auditar "cada SELECT" (inviável). Auditar: visualizar detalhe sensível, listar conjunto, exportar, alterar escopo, break-glass.
